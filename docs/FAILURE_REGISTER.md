# Failure Register

| ID | Failure mode | Impact | Detection | Mitigation / containment | Residual |
|---|---|---|---|---|---|
| FR-001 | Agent starts coding before understanding the product | Polished page markets the wrong problem | Compare page thesis to primary-source incidents and PDD | Product-truth gate before creative generation | Human interpretation can still be wrong |
| FR-002 | Page sounds like generic AI marketing | Low trust, low recognition, interchangeable positioning | Read-aloud / specificity review | Human-voice rewrite, audience utterances, concrete scenarios | Taste remains subjective |
| FR-003 | Evidence page takes over the sales story | Visitor sees an audit system before they care about the problem | Narrative review | Keep provenance as receipts/secondary evidence surface | Assurance products may legitimately need more technical proof |
| FR-004 | External paper is presented as product proof | Misleading efficacy claim | Claim-source review | Separate external support from measured product results | Some wording still requires judgment |
| FR-005 | Market gap ignores existing competitors | False novelty and weak investor story | Competitor/substitute map | Research direct and adjacent alternatives before positioning | Market changes after research |
| FR-006 | All candidates converge on the same design | Gallery creates false choice | Side-by-side visual review | Force materially different metaphors, typography, composition, motion, and emotional goals | Shared product truth will naturally create some overlap |
| FR-007 | OSS tools are adopted because they are interesting, not useful | New complexity without better output | Compare to native HTML control | Reuse only if an adapter clearly improves research, art direction, iteration, or production | Some benefits appear only over repeated use |
| FR-008 | Tool is credited despite not being executed | Misleading experiment results | Adapter record | Use `informed by` unless tool actually touched artifact | Manual interpretation may still be imperfect |
| FR-009 | Three.js is decorative and slows the page | Worse usability with no narrative benefit | Human and performance review | Require 3D to embody product mechanism; keep semantic fallback | WebGL variance across devices |
| FR-010 | Three.js CDN/import fails | Blank hero or broken page | Simulated import failure / fallback inspection | HTML content renders independently; canvas is enhancement | External CDN still affects enhancement |
| FR-011 | Gallery accidentally becomes public navigation/SEO content | Experiments look endorsed | Project navigation + sitemap review | No homepage links, no sitemap entry, `noindex` metadata | Direct URL remains shareable by design |
| FR-012 | Human owner feels forced to choose among weak candidates | Bad design gets promoted because experiment says so | Owner review | Explicit `reject all` outcome | Requires willingness to iterate |
| FR-013 | Research becomes stale | Positioning refers to outdated market | Source dates and recency review | Fresh web research for each major experiment | Market can still shift rapidly |
| FR-014 | Product detail is technically correct but emotionally distant | Target user does not feel understood | Audience-role critique | Start from user moment and desired progress | Different audiences may need separate variants |
| FR-015 | PAM itself becomes bureaucracy | Process cost exceeds creative benefit | Track whether artifacts change decisions | Keep PAM subset bounded; no runtime system; human can waive/defer with rationale | Methodology still has overhead |
